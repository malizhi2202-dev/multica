# D-discovery — 议题发现阶段（事实文档驱动）

> 九阶段的**法定前置阶段**（kind: discovery）：想法模糊、要系统性找改进点、评估某方向时先走这里。
> 议题即 change（R16.5）：本阶段与主干共用同一对象模型——真 change-id、语义工件、门禁登记、STATE 状态行、随步落盘。
> **规则唯一源是 `RULES.md` R16**（零代码改动 / 事实依据 / 落盘与审核状态 / 三轮上限 / 议题即 change / 状态行 / GD 门），本文件只定义执行步骤。

---

## 工件（全部落 `.specs/<change-id>/` 本层，R16.5）

> 结构模板：`@code-kit/templates/TOPICS.md` / `@code-kit/templates/DISCOVERY-SUBTOPIC.md` / `@code-kit/templates/ROADMAP.md`

| 工件 | 内容 | 写入时机 |
|---|---|---|
| `TOPICS.md` | 议题申报：问题定义 + 事实底座清单 + **子议题状态表**（每行：slug / 一句话 / 依据 / 轮次 / 审核标）+ 轮次记录 | 第 0 步产出，随每步更新 |
| `D-<子议题slug>.md` | 一个子议题一份，五节对应 ①-⑤；**头部状态标** `> 审核: 待审|通过|否决（第N轮）` | 每步完成即追加对应节（R16.3 随步落盘） |
| `ROADMAP.md` | 只汇总**已过审**子议题的结论 + 《建议改动清单》+ 落地顺序 | 每次有子议题过 ⑤ 门时更新 |

审核状态以 `TOPICS.md` 状态表 + 各子议题工件头部标为唯一证据；未过审的子议题文件存在但状态为"待审/否决"，其结论**禁止**进 ROADMAP、禁止被下游引用。清窗恢复：先读状态表，已过审不重跑（R16.6）。

**超量拆包（R16.8）**：单个 `D-<子议题>.md` 预计超 250 行 / 25 KB → 直接用文件包形态 `D-<子议题slug>/`：`TOPIC.md`（索引 + 状态标在头部）、`BRAINSTORM.md`、`RECON.md`、`CONCLUSION.md`、`PANEL.md`、`REVIEW.md`——五步各成一文件，语义与单文件五节完全同型；跨轮重跑在对应成员文件内追加新轮节。

## 第 0 步 · 扫描事实文档 → 拆子议题（强制第一步）

### 0.1 只读收集事实

- **流程工件**：`.specs/` 下全部 CHANGE/REQUIREMENT/DESIGN/TASK/REVIEW、`.specs/CONTEXT.md`、`.specs/LESSONS.md`、根 `STATE.md`
- **代码与配置（只读）**：目录结构、关键模块入口、配置文件、依赖清单、README
- **数据与材料**：用户提供的文件、日志、指标、用户原话里的事实
- **缺失声明**：读不到就明说"缺什么"请用户补——**不凭空拆解**

### 0.2 拆解规则

- 拆出 **2-5 个**子议题，每个必须是能独立走完五步的具体问题
- **每个子议题必须标注依据**（R16.2）：`依据：.specs/x/REQUIREMENT.md §2` / `依据：src/a/b.ts 的 X 逻辑` / `依据：用户原话"…"`
- 拆解维度：现状痛点 / 用户价值 / 技术可行性 / 竞品差距 / 风险点
- **反例**：无依据的"要不要做个 XX"不许列为子议题

### 0.3 落盘与推进

拆完即写 `TOPICS.md`（含状态表，全部"待审"）+ 首次建目录时写 STATE.md 行 `D-discovery: 议题 <slug> 第 1 轮拆解完成`，随即进入子议题逐个讨论——**不等用户确认拆解结果**（拆解依据已在表中自证；用户想纠偏随时可说）。

### 0.4 拆不出的分支

实在拆不出任何**有事实依据**的新子议题 → **停止循环，不重复**：说明"已无新子议题"，输出已有汇总与《建议改动清单》，问用户是否进入下一阶段（进入下一阶段 ≠ 重复循环）。

## 五步流程（每个子议题走完，不许跳步；每步完成即写入 `D-<子议题slug>.md` 对应节）

### ① 头脑风暴发散（技法内联，无外部依赖）

先静默发散再收敛：每轮 8-15 个候选方向，按"影响面 × 可行性"初排。可用技法（按需选 2-3 种，说明用了哪种）：

- **SCAMPER**：对现状逐问 替代/合并/调整/修改/他用/消除/重组
- **六顶帽**：事实→情绪→风险→价值→创造→流程 六视角各出 2 条
- **逆向**：问"怎么把这个问题弄到最糟"，倒推出防御点
- **假设反转**：把一条既有假设反过来说，看是否仍成立
- **类比迁移**：从第 0 步事实里找相邻模块的成熟做法平移过来

必须带上第 0 步的事实依据作为约束（每个候选标注它回应哪条事实）。

### ② 竞品与其他产品做法分析

对 Top 3-5 候选逐个查：其他产品怎么做、成熟模式、踩过的坑。

- **能联网**：真实检索（遵循 R11.1 探测），给出来源链接
- **不能联网**：基于既有知识作答，**显式标注"未联网验证"**
- 每个候选记录：产品名 / 做法 / 可借鉴点 / 不可取点

### ③ 总结结论与建议

自己完成。产出：**结论**（推荐 1-3 个方向 + 引用①②证据）、**建议**（每方向一句话落地路径）、**否决记录**（被否方向 + 理由）。
结论打磨用一轮批判技法（任选其一）：苏格拉底（逐条假设反问）/ 第一性原理 / 预演失败（假设上线失败倒推）/ 红队（专攻最弱一环）。

### ④ GD 议题门（正式减配门禁，R16.7）

复用 code-kit 角色体系，组 **3 人评审团**：`R-高级产品经理`（用户价值）+ `R-前端架构师` 或 `R-研发负责人`（技术可行性）+ `R-领域专家`（业务合理性；无对应领域时用 `R-资深用户评测员` 代替）。每位按 R13.3 投票格式给出：同意 / 有保留 / 反对 + 一句话理由。

- 全票通过 / 多数（≥2/3）→ 采纳，进入 ⑤；**禁止**再问"是否继续"
- 平票 / 全票反对 → 按澄清触发①（歧义）提交用户拍板，附各方理由

### ⑤ 人工审核门（法定硬停点，R16.3/R18.2）

以对话形式呈现该子议题结论（文件已全部落盘，此处只请用户裁决状态）：

> **议题**：…（依据：…）
> **结论**：推荐 X、Y
> **GD 门**：PM 同意 / 架构有保留（理由） / 领域 同意
> **影响面**：…（涉代码则附《建议改动清单》，并声明"本阶段不执行代码改动"）
> **工件**：`D-<slug>.md`（当前状态：待审）

明确问：**"此子议题是否通过？"**

| 用户回应 | 动作 |
|---|---|
| 通过 / 审核完毕 / OK | 头部状态标改"通过"（引用用户原话 + 时间）→ 汇入 `ROADMAP.md` → 更新 `TOPICS.md` 状态表 → STATE.md 记一行 → 进入下一个子议题 |
| 有修改意见 | 状态标改"否决（第N轮）"+ 意见记入第 ⑤ 节 → 带意见回到 **①** 重跑本子议题（新内容追加为新轮次节，不抹历史） |
| 沉默 / 不确定 / 追问细节 | 停在 ⑤，状态保持"待审"，不进下一个 |

## 三轮重复规则（R16.4）

**一轮 = 一次"扫描事实 → 拆子议题 → 所有子议题走完五步并过审"**。

| 轮次 | 做什么 |
|---|---|
| 第 1 轮 | 扫描事实 → 拆主议题的子议题 → 逐个走五步 + 过审 |
| 第 2 轮 | 重新扫描（含上轮已过审结论）→ 再挖下一层子议题 → 同上 |
| 第 3 轮 | 同上 |

每轮结束重新执行第 0 步拆解判断：**拆得出**（有事实依据）→ 继续；**拆不出** → 停止，不重复——不硬凑、不擅自开第 4 轮、不重炒已讨论过的冷饭。轮次记录写进 `TOPICS.md`。

## 与主干的衔接（议题即 change，R16.5）

- **立项**：议题过审且要落地 → **同一 change 目录**补写 `CHANGE.md`（why/what 直接引用 `ROADMAP.md` 结论），续走 REQUIREMENT 起的主干；`TOPICS.md`/`ROADMAP.md` 成为其上游工件，G1 需求门按 R2.7 检查其存在
- **只留档不立项**：工件留在本 change 目录，STATE.md 记"已留档议题 <slug>"；未来任何 change 引用 ROADMAP.md 路径即可
- **暂缓项消化**（R18.4）：主干任何阶段冒出的"先不做/下轮再说"登记进 `TOPICS.md` 状态表（标"待拆轮"），由下一轮 D-discovery 统一消化
- 与 `S-align` 的关系：D-discovery 产出建议、不改代码；S-align 检测五层漂移。两者都只读，可任意先后

## 自检清单（阶段出口）

- [ ] `TOPICS.md` 状态表与实际文件状态标一致，无"凭记忆声称已过审"
- [ ] 每个"通过"状态都能指回用户原话 + 时间（在第 ⑤ 节内）
- [ ] `ROADMAP.md` 只含已过审结论；《建议改动清单》逐条有文件/行号依据
- [ ] STATE.md 有本阶段的状态行（R16.6）
- [ ] 零代码改动（R16.1）：`git status` 无源码变更
